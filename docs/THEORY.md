# THEORY — 从"研究信号"到"商业信号" / From Research Signal to Commercial Signal

> 中文为主，English sections inline where useful.

## 0. 问题定义（为什么这是"正交"的）

已有的词频/共现类项目（例如基于 arXiv 短语共现网络 + 有效电导的做法）预测的目标是
**词汇事件**："概念 A 和概念 B 何时第一次出现在同一篇论文里"。
这本质上是链接预测（link prediction）在词汇表层上的应用，回答的是"人们会怎么说话"，
而不是"世界会怎么变化"。

本项目预测的目标变量不同——**商业化事件**：

> 一个研究主题 T，在未来 H 年内，其**商业信号**（专利、开源实现、包下载量、
> 工程岗位需求）是否会出现显著增长？

科学价值体现在三个区别上：

1. **目标不同**：共现 ≠ 商业化。Transformer 论文共现爆发在 2018 年，
   GPU 采购和推理框架下载爆发在 2022–2023 年。预测后者才有商业意义。
2. **数据源不同**：单一语料（arXiv 标题/摘要）→ 多源信号融合（文献 + 代码 + 包生态 + 专利）。
   多源三角验证（triangulation）是计量学的基本纪律，单源词汇统计不是。
3. **评估纪律不同**：只报"比随机好 2 倍"不算证据。
   必须报告与**强基线**（持续性和共同邻居类启发式）相比的**增量**，
   且用**走前式时间切分**（walk-forward）防止未来信息泄漏。

## 1. 数据来源（全部免费 / 无墙 / 可脚本化）

| 源 | 内容 | 访问方式 | 角色 |
|---|---|---|---|
| **OpenAlex** | 2.5 亿+ 文献元数据，自带 Topics（约 4500 个主题，三级学科树） | REST API，无需 key（polite pool: 加 `mailto` 即可 10 req/s） | 研究信号 + 主题本体 |
| **GitHub REST API** | 每个主题关键词的年度新建仓库数 | 无 token 10 req/min；`GITHUB_TOKEN` 环境变量提速至 30/min | 工程化信号（"有人开始造轮子"） |
| **Stack Exchange API** | StackOverflow 每个 tag 的年度提问数 | REST，无 key（300 req/day，磁盘缓存后足够） | 社区采用信号（"有人在用、在踩坑"） |
| **PatentsView**（可选） | 美国专利全文 + CPC 分类 | REST，需免费 key | 法律确权信号（"有人在圈地"） |

数据源选择的诚实说明：OpenAlex 的 `group_by` 分桶只返回论文计数（不含引用合计），
pypistats.org 只保留近 6 个月下载量——这两个看似顺手的数据其实拿不到。
我们因此采用"论文量 + 新建仓库 + SO 提问量"三信号，都是**可脚本化、免 key、
可完整回溯**的年度序列。宁要三个诚实的信号，不要一个拿不到的漂亮信号。

关键设计：**不自建词表**。OpenAlex Topics 是人工+算法维护的本体，
直接绕开了"n-gram 抽取 + 停用词表"这一整套既脆弱又无法复现的环节
（对方的"字节级复现词典"恰恰说明这个环节脆弱到需要专门声明复现性）。

## 2. 数据结构与算法

### 2.1 主题时间序列（核心数据形态）

每个主题 T 是一条多变量年度序列：

```
S(T) = { (papers_y, repos_y, questions_y [, patents_y]) }_{y=y0..yn}
```

存储：按主题分区的 JSONL / SQLite（标准库 `sqlite3`），**流式写入**，
任何时刻内存中只有一个主题的数据——这是对"16G 内存跑 48 小时"问题的直接回应：
**这个管线在 4G 内存的机器上也应能跑完**，因为它从不物化全量图。

### 2.2 趋势检测算法

**(a) 动量指标（momentum）**
- YoY 增长率、3 年 CAGR、以及 z-score 化的动量：
  `z(T,y) = (g(T,y) - μ_field(y)) / σ_field(y)`
  —— 按所属学科（field）内标准化，避免"AI 什么都涨"的整体通胀淹没横截面信号。

**(b) Kleinberg 突发检测（burst detection）**
两状态自动机（quiet/burst），状态转移代价 `γ·ln(n)`，
用 Viterbi 风格的 DP 在 O(n·states) 内求最优状态序列。
输出：每个主题的 burst 区间列表。**正在 burst 且此前从未 burst 过的主题**
是最有价值的"早期信号"类别。参考：Kleinberg, "Bursty and Hierarchical
Structure in Streams", KDD 2002。

**(c) 主题共现图 + 链接预测指标（基线组）**
以 OpenAlex 论文的 topics 列表构建主题共现图（节点=主题，边权=共现论文数，
按年切片）。对每个未连边主题对计算四个标准启发式：

- Common Neighbors: `|Γ(A) ∩ Γ(B)|`
- Jaccard: `|Γ(A)∩Γ(B)| / |Γ(A)∪Γ(B)|`
- Adamic-Adar: `Σ_{v∈Γ(A)∩Γ(B)} 1/log|Γ(v)|`
- Preferential Attachment: `|Γ(A)|·|Γ(B)|`
- （参照项）两跳有效电导 G(A,B) —— 即对方项目的核心指标，
  在此**仅作为基线之一**参与对比。这正是检验"电路隐喻是否有增量"的诚实做法。

图用邻接表（dict of dicts）+ 按年切片，单年规模（数千主题节点）在任何机器上都很轻。

**(d) 商业化综合指数 CSI（Commercial Signal Index）**

```
CSI(T,y) = Σ_i w_i · minmax_norm( s_i(T,y) )
```

其中 `s_i` 为各商业信号（新建仓库数、SO 提问量、论文数，可选专利数），
权重 `w_i` 在 `pipeline/topics.py` 中显式声明、可按领域调整；
**逐年 min-max 归一化**以避免各信号整体膨胀造成的尺度漂移。

### 2.3 预测模型与评估协议

任务形式化为二分类：给定主题 T 在年 y 的特征向量
`X(T,y) = [动量, burst 状态, 图中心性, 各商业信号滞后值, 共现图启发式最大值]`，
预测 `Y(T,y) = 1{ CSI(T, y+H) - CSI(T, y) > θ }`。

- 模型：**逻辑回归**（sklearn, L2）。刻意不用深度学习——
  样本量是"主题×年"（千级），复杂模型只会过拟合；
  线性模型的系数还自带可解释性，直接回应"不可解释的黑箱"批评。
- 评估：**walk-forward 时间切分**——用 ≤y 年的数据训练，预测 y+1..y+H，
  滚动前进。绝不允许随机切分（那会泄漏未来）。
- 指标：ROC-AUC、PR-AUC、Brier score（校准度）。
- **基线**：① 持续性基线（"明年和今年一样"）；② 全局均值基线；
  ③ 仅用共现图启发式的模型（= 对方方法论的忠实复现）。
  报告**相对于基线③的增量**——这是对"灌水质疑"的正面回应：
  如果多源信号没有增量，我们自己承认。

## 3. 与对标项目的方法论对照

| 维度 | 共现-电导类项目 | 本项目 |
|---|---|---|
| 预测目标 | 词汇首次共现 | 商业信号增长 |
| 数据源 | 单一语料 | 文献+代码+包+专利 多源 |
| 词表 | 自建 n-gram（脆弱） | OpenAlex Topics 本体 |
| 基线 | 随机 | 持续性 + 均值 + 共现启发式 |
| 时间验证 | 单次回测 | walk-forward 滚动 |
| 硬件需求 | 16G/48h | 流式，4G 可跑 |
| 可证伪性 | 弱（故事性强） | 强（每年自动回测，错了公开） |

## 4. 已知的诚实局限（写在这里，免得别人说）

1. OpenAlex Topics 粒度较粗，新兴主题有 1–2 年注册延迟 → 我们预测不了
   "还没被命名的领域"。
2. GitHub/SO 信号偏向 CS/工程领域，对数学、理论物理的商业化几乎失明。
3. 专利数据仅美国（PatentsView），忽略 EU/CN/JP。
4. "商业化"的代理变量不等于真实营收——这是所有计量研究的共有限制。
5. 样本量小（主题×年），结论应被视为**排序参考**而非精确预测。
